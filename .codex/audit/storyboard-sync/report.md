# 分镜制作同步审计

审计时间：2026-07-20

范围：Rust Toon 项目页 `/toonflow/projects/1784265252790` 的“分镜制作”，对照 `/home/xiuran/code/Toonflow-app` 1.1.8 的分镜制作体验与服务端能力。

## 截图步骤

1. 当前项目入口：登录后可进入项目，健康度一般。
2. 当前分镜制作：页面可打开，但画布、Agent 和操作区失衡，健康度差。
3. ToonFlow 参考分镜面板：分镜/资产卡片在同一画布中可见，Agent 固定在右侧，健康度良好。
4. ToonFlow 参考分镜表：分镜表、分镜卡片和阶段说明同屏，健康度良好。

## 结论

当前实现完成了“数据展示和 Agent 对话”的骨架，但没有同步 ToonFlow 的核心生产工作台。主要差距不是配色，而是：画布结构被改成固定五阶段；分镜卡片缺少单条/批量操作；分镜生成状态没有前端轮询闭环；轨道聚合逻辑与 ToonFlow 数据模型不一致；右侧 Agent 在当前视口压缩主画布并产生明显可读性问题。

## 修复优先级

### P0：先修生产闭环

1. 恢复可操作分镜卡片：选择、编辑描述/提示词、关联资产、单条生成/强制重生成、删除、批量删除、进入图片编辑流。
2. 接入生成状态轮询和失败原因：显示未生成/生成中/已完成/生成失败，支持失败重试；不能只提交批量任务后靠手动刷新。
3. 修正轨道聚合：同一 `track` 的分镜必须共享 `trackId`，轨道时长为组内分镜时长合计；删除最后一条分镜时同步清理轨道和图片流。
4. 补齐批量接口/前端调用：`batchDelete`、`pollingImage`、`editStoryboardInfo`、`updateStoryboardUrl`、下载合成预览，并确保项目范围校验。

### P1：恢复 ToonFlow 的工作台结构

1. 不再把所有内容排成 x=40/1080/1680/2440 的固定流水线。分镜表与分镜卡片应是可平移、可缩放、可聚焦的工作区，并支持定位当前阶段。
2. 资产卡片与衍生资产保持成对关系和清晰箭头；分镜卡片按 Track 分组，显示缩略图、序号、时长、状态和关键操作。
3. Agent 右栏使用可折叠/可拖宽面板；主画布保留最小可用宽度。当前 1440px 视口下右栏覆盖且正文出现白底浅字。
4. 把“刷新/保存/新增/批量生成/预览”等工具按工作流分组，危险操作需要确认；生成按钮需展示选中数量和禁用原因。

### P2：可读性与无障碍

1. 修复 Agent 消息白底浅色文字的低对比度；深色主题下保持文本、边框和状态色一致。
2. 为图标按钮补充可访问名称；当前截图与无障碍树里存在多个空名称按钮。
3. 为画布节点提供键盘可达的替代导航、明确焦点样式，以及缩放/适应视图按钮文字提示。
4. 处理 1280/1440px 与窄屏重排；避免靠 0.68 默认缩放把正文压到不可读。

## 代码证据

- `ProductionFlowCanvas.vue` 使用固定节点坐标，且禁止拖拽和连接；分镜卡片只有图片和文本，无任何编辑/选择/重试动作。
- `detail.vue` 将主区固定为 18/24、Agent 为 6/24，导致中等视口下主画布与侧栏互相争抢空间。
- 当前前端只显式接入批量生成和合成预览，缺少 ToonFlow 已有的轮询、批删、更新图片 URL、下载预览等调用。
- Rust `batch_add_storyboards` 逐条插入且 `track_id=None`，没有 ToonFlow `batchAddStoryboardInfo` 中的按 track 分组、轨道创建与时长汇总。
- Rust `remove_storyboard` 只删分镜本身；ToonFlow 还清理关联图片流、资产关系，并在组内最后一条删除时清理视频轨道。
